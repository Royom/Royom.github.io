Agent Token Efficiency

一、 架构演进：Harness Engineering 与 Skill 规范

1.1 Skill 的结构与渐进式披露

在现代智能体系统中，Skill（技能）本质上是可复用、模块化的指令与执行规程。为了兼顾指引精度与上下文 Token 消耗，主流智能体采用了渐进式披露（Progressive Disclosure）与延迟加载机制。

1.2 Harness Engineering 的边际影响力定律

深入参考：一文读懂 Harness Engineering：从 14 篇工程文章中，寻找那个让 AI 不再离经叛道的壳

  1. 组件按需演进：Harness 的本质是弥补当前模型能力的缺陷（作为“外部假肢”）。当基座模型自我进化具备了某项能力后，对应的 Harness 组件就应被精简剔除。
  2. 影响力的三层位阶：Cursor 在数百个 Agent 协同运行的浏览器工程项目中发现：影响系统行为最大的因素是 Prompt（自然语言交互范式），其次是 Harness 架构设计，最后才是基座模型本身。
    • 前提条件：该结论建立在 Harness 已经具备成型的 Planner-Worker-Judge 三层体系之上。Prompt 是站在成熟 Harness 的肩膀上发挥出最大的边际调节能力。
  3. 长程任务的三层壳：
    • 记忆（Memory）：保障长程不忘事；
    • 并发（Concurrency）：支撑复杂大工程拆解；
    • 验证（Verification）：防止幻觉与敷衍，保障执行严谨度。

1.3 A Survey on AI Agent Harness 的技能体系

在一篇全面的 Harness 综述中，Skill 作为核心模块贯穿系统的关键层级： - Layer 2 (能力层)： - Acquisition（获取）：探讨智能体如何通过自我进化、多智能体交互或程序归纳习得新技能； - Selection and Routing（选择与路由）：当技能库规模暴涨时，如何通过“检索-重排（Retrieve-and-Rerank）”精准路由； - Optimization（优化）：通过结构化压缩降低 Token 消耗，以及多技能组合推理； - Evaluation（评估）：度量技能增强后的系统能力极限与 Benchmark 表现。 - Layer 4 (安全层)：关注运行时沙箱与权限管控。

二、 攻防前沿：Skill 安全威胁与投毒对抗

随着 Skill 从本地静态扩展走向开放生态，其可复用与代码执行特性使其成为智能体系统的重要攻击面（Attack Surface）。

2.1 隐式注入：Unicode 不可见字符投毒

参考分析：Skill 投毒技术剖析

  • 机理：利用特定 Unicode 编码在大部分常规编辑器中不可见的特性，肉眼无法察觉，但 LLM 的 Tokenizer 依然会将其切分为独立的 Token 并读取语义。攻击者借此在技能步骤中隐蔽植入恶意越权指令。
  • 系统防御：现代成熟 Harness（如 Codex 等）在系统入口处设立了多道防线：不可见字符静态过滤、指令-数据严格分离、高危命令沙箱隔离与审批拦截。

2.2 攻击策略的演进态势

参考分析：SKILL 攻击策略改进

随着基础防御的健全，攻击手段逐步从低级隐式注入转向高级语义对抗： 1. 明文引导激活：不再依赖 Tokenizer 缺陷，而是通过正常语义诱导模型在推理时主动寻址并执行隐藏指令。 2. 语义身份混淆：诱使模型误判恶意片段的“身份”（例如将其伪装成系统最高安全规则、工具调用规范或合规白名单）。 3. 内容投毒对抗（Content Poisoning）：退一步不直接触发高危动作，而是篡改技能自带的“安全规范/最佳实践”，在后续多轮推理中潜移默化地误导智能体。 4. 多步拆解绕过：将单次显眼的恶意意图拆解为多个彼此看似合法的中间步骤，通过跨工具链协同触发绕过安全检查。

2.3 大规模生态实证安全分析 (SKILLSCAN)

Agent Skills in the Wild: An Empirical Study of Security Vulnerabilities at Scale (arXiv: 2601.10338)

  • 核心工作：构建了融合静态规则分析与大模型语义分类的多阶段检测框架 SKILLSCAN，对两大核心开源市场的 31,132 个独立技能展开了首次系统审计。
  • 核心结论：
    • 生态中 26.1% 的技能 包含提示词注入、数据外泄、权限提升或供应链投毒等至少一种漏洞风险；
    • 携带可执行脚本的技能，其染毒风险是纯指令型技能的 2.12 倍，印证了运行时沙箱与权限隔离的极端重要性。

2.4 工程设计规范

参考分析：Agent Skills 组织与设计规范

设计工程化 Skill 时应兼顾 Token 效率与可靠性： - 精炼描述，用词严谨无歧义，消除无意义的客套废话； - 贯彻渐进式披露与按需加载：元数据暴露给路由层，主体长逻辑下沉为外部文件； - 合理界定自由度边界，规范参数输入/输出契约。

三、 规模化调度：Skill 路由与按需检索 (Routing & Selection)

当企业与社区的工具/技能库达到数千乃至数万规模时，将全部技能挂载入 Prompt 会瞬间撑爆上下文。如何高效召回最小必要技能集成为关键。

3.1 ⭐SkillRouter: 面向超大规模技能库的路由系统

SkillRouter: Skill Routing for LLM Agents at Scale

核心痛点与发现

在数万级高度同质化的真实技能池中，仅凭简短的元数据（名称与短摘要）检索，极易引发“特征缺失”，模型无法甄别实现细节相似的干扰技能。 - 关键经验发现：技能的完整文本（尤其是详细实现代码与规范边界）包含了简短描述无法替代的细粒度路由信号。提供全文感知能大幅提升小模型判别重叠技能的能力。

系统流程 (训练与推理)

  1. 离线与训练阶段：
    • 微调一个 0.6B 双塔检索器，采用假负例过滤机制，学习 Query 与技能全文的粗排关联；
    • 微调一个 0.6B 排序模型，输入 Query 与第一阶段召回的 Top-20 技能，采用列表级交叉熵（Listwise Cross-Entropy）精细重排。
  2. 线上推理阶段：
    • 提前离线计算全部技能的全文向量；
    • 实时计算 Query 与技能库的余弦相似度召回 Top-20；
    • 拼接上下文送入轻量重排模型，精准挑选最终的 Top-\(k\) 技能注入上下文。

3.2 SkillsInjector: 动态上下文注入

SkillsInjector: Dynamic Skill Context Construction for LLM Agents (arXiv: 2605.29794)

相比静态选取固定 Top-\(k\) 个技能，SkillsInjector 强调按需动态确定注入技能的数量与范围，避免因机械式的固定 \(k\) 值在简单任务中引入冗余 Token、在复杂任务中遗漏必要工具。

3.3 AutoTool: 基于工具惯性图绕过大模型推理

AutoTool: Efficient Tool Selection for Large Language Model Agents (arXiv: 2511.14650)

核心设计思想

AutoTool 提出在高度可预测的决策链路中绕过大模型以节约推理 Token 与延迟。系统根据历史交互轨迹构建动态的“工具惯性图（Tool Inertia Graph, TIG）”，捕捉步骤间转移规律与参数数据流。 - 综合惯性潜力得分（CIPS）： \[\text{CIPS} = \text{Combine}(\text{Score}_{\text{freq}}, \text{Score}_{\text{ctx}})\] 融合状态转移频率与当前语义相似度，预测下一步工具并尝试自动填充参数。只有当置信度不足或填参失败时，才回退由 LLM 处理。

启发：架构改造思路

  1. 轻量预处理路由层：在请求提交给 LLM 前，引入类似 CIPS 的打分机制动态筛选出当前步骤最迫切的 Top-\(k\) 技能，仅注入其 Schema，从源头压低 Input Tokens；
  2. 控制流与数据流解耦（状态白板）：在 Harness 中维护全局参数流动图。如果 Skill B 的输入直接取自 Skill A 的历史输出（如 UUID、数据块），由框架底层通过键值匹配自动搬运填参，无需让大模型在上下文里反复“复读”这些长文本。

3.4 SkillRet: 技能检索基准数据集

SkillRet: A Large-Scale Benchmark for Skill Retrieval in LLM Agents (arXiv: 2605.05726)

构建了大规模技能检索的标准评测基准，包含详尽的 Query-Skill 匹配对，专门用于评估和训练智能体在海量技能库中的召回与重排精度。

除了减少选中的技能数量，优化每个技能文本本身的表达密度同样是降低 Token 消耗的直接途径。

4.2 SkillSmith: 编译技能为边界引导的运行时接口

SkillSmith: Compiling Agent Skills into Boundary-Guided Runtime Interfaces

核心思路：将传统的冗长自然语言 Skill 说明，在离线阶段编译抽象为轻量级结构化接口（Runtime Interfaces），解决无关 Skill 干扰与重复推理问题。

编译与执行机制

  • 分析与分类：分析 Skill 文本，提取控制步骤依赖图与边界校验条件；
  • 接口生成：向 Agent 暴露轻量、规范的 Schema 接口与策略检查点；
  • 执行拦截：运行时通过策略拦截器保障调用的合规性与参数准确度，显著压缩 Prompt 开销。

4.3 经典基线与工具边界探讨

  • LLMLingua：广泛使用的通用 Prompt 抽取式压缩 Baseline，通过小模型计算 Token 困惑度剔除高冗余 Token。但在结构化极强的 Agent 场景中，易误损关键参数标识符。
  • GRAFT (Graph-Tokenized LLMs for Tool Planning)：通过图标记化扩充词表微调优化工具调用顺序。但泛化性受限，对于未见过的工具表现乏力，且随着前沿模型推理能力跃升，专用图词表的性价比逐渐降低。

五、 深度专题：从推理轨迹蒸馏结构化经验卡片 (TRS 与批判性诊断)

将多轮试错的漫长轨迹在离线阶段提炼为结构化“经验卡片”，在线以极小的 Token 开销注入引导，是近年来极具潜力的研究方向。

5.1 ⭐Thinking with Reasoning Skills (TRS): 范式转换

Thinking with reasoning skills: Fewer tokens, more accuracy (arXiv: 2604.21764)
参考解读：微信公众号简要解读

a) 核心理念

TRS 实现了一次关键的范式跃迁：将“从头开始盲目推理（Reasoning from scratch）”转变为“基于回忆经验的启发推理（Reasoning with recalled experience）”。

b) 技能卡片结构规范 (Skill Card Schema)

每张卡片遵循规范化的 5 字段设计： 1. Trigger：触发条件与问题特征； 2. Do：推荐的高效解题路径； 3. Avoid：避免踩入的试错陷阱（从失败轨迹提取）； 4. Check：关键边界与中间核验点； 5. Risk：潜在的失效模式。

c) 实验成效与数据细节

在数学推理与编程竞赛基准上，TRS 展现出显著的 Token 削减成效： - 数学推理基准（DEEPMATH-103K，93K 建库 / 10K 测试，BM25 \(k=1\)）： - Doubao-Seed-1.8 Pro：准确率基本持平（\(95.1\% \to 94.9\%\)），Token 消耗骤降 59.1%（\(3,453 \to 1,411\)），综合成本削减 53.8%； - Gemini-3-Flash：准确率提升 +0.7%（\(94.8\% \to 95.5\%\)），Token 消耗降低 18.5%，成本降低 17.5%； - GPT-OSS-120B：准确率维持 \(93.7\%\)，Token 消耗减少 22.4%； - GPT-4o-mini：准确率提升 +1.8%（\(59.6\% \to 61.4\%\)），成本降低 6.9%。 - 编程竞赛基准（NEMOTRON-COMPETITIVE-PROGRAMMING-V1，26.6K 建库 / 1K 测试，混合检索 \(k=5\)）： - Gemini-3-Flash：保持高 pass@1（\(72.0\% \to 71.7\%\)），Token 消耗降低 15.5%； - GPT-OSS-120B：pass@1 提升 +4.1%（\(54.2\% \to 58.3\%\)），成功突破性能瓶颈。

5.2 批判性反思：Scaffolding, Not Stronger Reasoning 的深度诊断

Scaffolding, Not Stronger Reasoning: Diagnosing Skill-Card Retrieval for Mathematical Problem Solving (OpenReview)

该工作对 TRS 提出了尖锐且深刻的学术批判：TRS 并没有从本质上增强模型的推理核心，而只是为基础较弱的模型提供了一个外部“脚手架（Scaffolding）”。对于强大的前沿基座，外挂卡片甚至会带来负向损害！

核心诊断论点

  1. 相关性 \(\neq\) 严格数学适用性（Relevance \(\neq\) Applicability）：
    • 现有的 RAG 与文本相似度指标主要衡量语义相关，但数学/代码任务对边界条件有着绝对严格的适用要求。
  2. 强模型的“干扰项陷阱（Distractor Effect）”：
    • 强模型本身已具备完备的推导逻辑。即便检索到 Top-1 的技能卡片，若该卡片在数学细节上存在微小偏差，模型也会被其牵引，导致原本能解出的题目被误导做错。
  3. 致害机制细分：
    • Top-1 卡片致害：主因是“过度谨慎的限定（Over-cautious qualification）”（8/11 案例）。卡片诱导模型考虑了原题并未要求的额外边界，将常规作答演变为严苛的分支讨论。
    • 低排名卡片致害：主因是“符号/数值漂移（Symbolic drift）”，诱使模型走入冗长而不稳定的复杂推导链。
  4. 词法检索的失效：
    • 统计显示，有害案例与完全正确案例的 BM25 分数差距并无统计显著性（中位数 9.83 vs 10.71）。单纯依赖检索分数根本无法阻断具备干扰效应的不适用卡片。

六、 进阶前沿：Skill 自进化与测试时自适应 (Evolution & Test-Time Adaptation)

静态构建的技能库终究无法穷尽开放世界的动态约束，让智能体在交互中自我沉淀、进化与修正技能成为前沿热点。

6.1 SoK: 智能体技能生命周期与自生成陷阱

SoK: Agentic Skills — Beyond Tool Use in LLM Agents

a) 技能的标准全生命周期链路

\[\text{发现 (Discovery)} \longrightarrow \text{实践/提炼 (Practice)} \longrightarrow \text{蒸馏 (Distill)} \longrightarrow \text{存储 (Store)} \longrightarrow \text{检索/组合 (Retrieve)} \longrightarrow \text{执行 (Execute)} \longrightarrow \text{评估/更新 (Update)}\]

b) 自生成技能的性能下滑陷阱

实证统计显示，缺乏强约束的自生成技能容易产生精度反噬： - 人工策划技能平均使基准提升 16.2 个百分点； - 自生成技能平均反而下降 1.3 个百分点。 - 根本原因：模型自主归纳时极易编码进错误或过于狭隘具体的局部启发式模式（Incorrect or overly specific heuristics）。

Skills on the Fly: Test-Time Adaptive Skill Synthesis for LLM Agents (arXiv: 2605.16986)

6.3 ⭐Skill Self-Play: 基于双流协同进化的技能自对弈

Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills

核心机制

针对无约束任务生成容易导致“合成数据崩溃”的问题，设计了出题模型与解题模型协同自进化的三项机制：

  1. 双流生成（Dual-Stream Generation）：
    • 技能流：严格依据现有技能出题，提供结构先验；
    • 开放探索流：脱离既有技能拘束，向未知任务空间探路；
    • 保持 \(1:1\) 比例混合，既防止过拟合退化，又避免无序发散崩溃。
  2. 门控课程奖励（Gated Curriculum Reward）：
    • 奖励函数锚定在解题者的能力前沿（成功率 0.5 附近最理想）；
    • 设立“任务有效性硬门控”，斩断通过生成不可解难题骗取奖励的作弊行为。
  3. 动态技能库进化（Refine, Prune, Induce）：
    • Refine：从失败案例中修正已有技能；
    • Prune：淘汰已饱和的低价值简单技能；
    • Induce：从探索流的高价值新任务中诱导出新技能包。

6.4 SkillMOO: 多目标帕累托技能优化

SkillMOO: Multi-Objective Optimization of Agent Skills for Software Engineering

核心特色：以平衡“任务通过率”与“Token 消耗成本”为目标，利用双智能体交互寻找技能集合的帕累托最优解（Pareto Optimal）。

极具启发的实证结论（38 次有效优化逆向分析）： - 移除技能（Remove Skills，发生 16 次）：是带来正向收益最核心的操作！清理歧义与偏离主题的冗余技能，能同时提升准确率并降低 Token 消耗； - 替换技能（Replace Skills，发生 7 次）：用高密度、精确指令替换宽泛指令； - 新增技能（Add Skills，发生 9 次）：无一例（0/9）成功提升通过率，盲目堆砌技能往往弊大于利。

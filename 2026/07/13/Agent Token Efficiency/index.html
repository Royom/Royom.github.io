Agent Token Efficiency

一、Skill 结构与 Harness Engineering

1.1 Skill 的结构与渐进式披露

Skill（技能）可以理解为一组可复用的指令、脚本和执行约束。为了避免每次都把完整内容放进上下文，Agent 通常只先暴露名称和简介，选中后再加载正文或参考文件，即渐进式披露（Progressive Disclosure）和延迟加载。

1.2 Harness 对 Agent 行为的影响

参考：一文读懂 Harness Engineering：从 14 篇工程文章中，寻找那个让 AI 不再离经叛道的壳

  1. 组件应随模型能力调整：Harness 主要补足当前模型在执行、状态管理和验证上的不足。当模型已经能稳定处理某项能力时，相应组件可以简化或移除。
  2. Prompt、Harness 与模型共同决定行为：文中根据 Cursor 的工程案例，将影响因素概括为 Prompt、Harness 和基座模型，并认为在已有成熟 Planner-Worker-Judge 架构的前提下，Prompt 的边际影响最大。这更适合作为特定工程经验，而不是普遍规律。
  3. 长程任务常见的三个支点：
    • 记忆（Memory）：保存长程状态；
    • 并发（Concurrency）：拆分并行任务；
    • 验证（Verification）：检查结果并限制错误继续传播。

1.3 Harness 综述中的 Skill

A Survey on AI Agent Harness

这篇综述将 Harness 分为四层，而不是把 Skill 单独列为“能力层”：

  1. 执行与编排（Execution & Orchestration）；
  2. 上下文与轨迹管理（Context & Trajectory Management）；
  3. 交互界面与执行环境（Interaction Surface & Execution Environment）；
  4. 约束与护栏（Constraints & Guardrails）。

Skill 会跨越其中几层：路由和调用属于执行编排，技能正文的加载属于上下文管理，脚本运行涉及执行环境，权限与安全检查则落在约束层。这样看，Skill 更像 Harness 中贯穿多个环节的组织形式，而不是一个孤立模块。

二、Skill 安全（暂时归档）

Skill 从本地扩展走向开放生态后，指令和可执行代码都可能成为攻击入口。这一部分暂时归档，但保留几类和工程实现直接相关的问题。

2.1 Unicode 不可见字符注入

参考：Skill 投毒技术剖析

机理： 部分 Unicode 字符在常规编辑器中不明显，但仍会进入 Tokenizer。攻击者可以利用这一点，在技能步骤里隐藏越权指令。

防护： 可在入口处做不可见字符检查，并通过指令与数据分离、沙箱、最小权限和高风险操作确认来降低影响。仅靠字符过滤并不能覆盖语义层面的攻击。

2.2 从字符注入到语义投毒

参考：SKILL 攻击策略改进

  1. 明文引导激活：用正常文本诱导模型定位并执行隐藏指令，不再依赖字符编码问题。
  2. 语义身份混淆：把恶意内容伪装成系统规则、工具规范或白名单说明。
  3. 内容投毒（Content Poisoning）：篡改技能内的安全规范或最佳实践，在后续任务中持续影响模型判断。
  4. 多步拆解绕过：把一个高风险目标拆成多个表面正常的步骤，再通过工具链组合完成。

2.3 SKILLSCAN 的生态分析

Agent Skills in the Wild: An Empirical Study of Security Vulnerabilities at Scale（arXiv: 2601.10338）

工作： SKILLSCAN 将静态分析和 LLM 语义分类结合起来。论文从两个开放市场收集了 42,447 个技能，并对其中 31,132 个进行了系统分析。

结果：

  • 26.1% 的技能至少包含一种漏洞模式，覆盖提示词注入、数据外泄、权限提升和供应链风险；
  • 带可执行脚本的技能出现漏洞的可能性是纯指令型技能的 2.12 倍。这里统计的是漏洞风险，不能直接等同于“恶意技能比例”。

2.4 工程侧防护

参考：Agent Skills 组织与设计规范

  • 描述尽量短而明确，减少歧义；
  • 使用渐进式披露：路由层只读取元数据，长逻辑和参考资料按需加载；
  • 明确输入、输出和权限边界；
  • 对脚本、网络访问和高风险命令单独校验。

三、Skill 路由与按需检索

技能库扩展到数千乃至数万项后，把所有技能都放入 prompt 已经不可行。问题变成了：怎样用较低开销找出当前任务真正需要的少量技能。

3.1 SkillRouter：大规模技能路由

SkillRouter: Skill Routing for LLM Agents at Scale（arXiv: 2603.22455）

问题与发现

在大规模且高度相似的技能池中，只依赖名称和短摘要，往往无法区分实现细节相近的技能。SkillRouter 的主要发现是：技能全文中的代码、约束和操作细节也能提供路由信号，因此可以在离线阶段利用全文训练检索器，同时保持在线检索的开销可控。

训练与推理流程

  1. 离线训练：
    • 微调 0.6B 双塔检索器，结合假负例过滤，学习 Query 与技能全文的粗排关系；
    • 微调 0.6B 重排模型，对第一阶段召回的 Top-20 技能做列表级重排。
  2. 在线推理：
    • 预先计算技能全文向量；
    • 根据 Query 召回 Top-20；
    • 由轻量重排模型选出最终的 Top-\(k\) 技能，再放入上下文。

3.2 SkillsInjector：动态构造技能上下文

SkillsInjector: Dynamic Skill Context Construction for LLM Agents（arXiv: 2605.29794）

SkillsInjector 不固定注入 Top-\(k\)，而是根据任务决定技能数量。它包含两个部分：Context Planner 学习要取哪些技能、取多少；Set-aware Renderer 再根据已选集合调整描述。这样可以减少简单任务中的冗余，也避免复杂任务因固定 \(k\) 过小而漏掉必要技能。

3.3 AutoTool：利用工具惯性减少 LLM 路由

AutoTool: Efficient Tool Selection for Large Language Model Agents（arXiv: 2511.14650）

核心方法

AutoTool 针对可预测的工具调用链，尝试减少工具选择阶段对 LLM 的依赖。系统根据历史轨迹构建工具惯性图（Tool Inertia Graph, TIG），同时记录工具转移和参数信息。

其综合惯性潜力得分（CIPS）可写为：

\[ \text{CIPS}=\text{Combine}(\text{Score}_{\text{freq}},\text{Score}_{\text{ctx}}) \]

系统根据转移频率和当前语义预测下一步工具，并尝试填充参数；置信度不足或填参失败时，再回退给 LLM。

对我的启发

  1. 增加轻量路由层：在调用 LLM 前先筛出当前步骤需要的 Top-\(k\) 技能，只注入相关 Schema。
  2. 分开控制流和数据流：Harness 可以维护参数状态。如果 Skill B 的输入直接来自 Skill A 的输出，例如 UUID 或数据块，就由框架完成传递，不必让模型在上下文里重复读取和转写。

3.4 SkillRet：技能检索基准

SkillRet: A Large-Scale Benchmark for Skill Retrieval in LLM Agents（arXiv: 2605.05726）

SkillRet 提供了面向大规模技能检索的训练和评测数据，包括 17,810 个技能、63,259 条训练样本和 4,997 条评测样本，用于比较技能召回与重排方法。

四、Skill 文本压缩与接口编译

除了减少注入的技能数量，还可以直接压缩单个技能的路由描述和执行正文。

4.1 SkillReducer：两阶段技能压缩

SkillReducer: Optimizing LLM Agent Skills for Token Efficiency（arXiv: 2603.29919）

SkillReducer 分别处理技能的路由描述和正文：

实验结果

  • 路由层平均压缩 48%，正文层平均压缩 39%；
  • 任务质量平均提升 2.8%；
  • 跨模型的平均功能保留率为 0.965。这些结果说明压缩可能同时减少干扰，但仍需要依赖测试集检查功能是否退化。

4.2 SkillSmith：编译为运行时接口

SkillSmith: Compiling Agent Skills into Boundary-Guided Runtime Interfaces（arXiv: 2605.15215）

核心思路： SkillSmith 在离线阶段分析自然语言 Skill，并生成较短的运行时接口，把部分步骤控制和边界检查移到 Harness 中，减少无关内容进入 prompt。

编译与执行

  • 分析与分类：从 Skill 文本中提取步骤依赖和边界条件；
  • 接口生成：向 Agent 暴露较短的 Schema 和策略检查点；
  • 运行时拦截：由框架检查调用条件和参数，避免每次都让模型重新解释整份 Skill。

论文报告求解阶段 Token 减少 57.44%、思考轮数减少 42.99%、运行时间减少 50.57%。这些收益依赖编译器正确提取边界，因此接口生成本身仍要验证。

4.3 通用压缩方法与边界

  • LLMLingua：用小模型估计 Token 重要性并做抽取式压缩。用于 Agent Skill 时，需要注意参数名、标识符和否定条件可能被误删。
  • GRAFT（Graph-Tokenized LLMs for Tool Planning）：通过图标记和扩展词表学习工具调用顺序。它依赖专门训练，对未见工具的泛化和新增词表的维护成本需要单独考虑。

五、从推理轨迹提取经验卡片

这一类方法把长推理轨迹离线整理为短的经验卡片，在线检索后再放进上下文。它节省的是重复探索产生的 Token，但效果取决于检索到的卡片是否真的适用。

5.1 Thinking with Reasoning Skills（TRS）

Thinking with Reasoning Skills: Fewer Tokens, More Accuracy（arXiv: 2604.21764；ACL 2026 Industry Track） 参考解读：微信公众号简要解读

核心思路

TRS 把历史推理轨迹整理为可检索的技能卡片。遇到新问题时，模型先取回相似经验，再结合当前问题完成推理。

技能卡片结构

  1. Trigger：适用的问题特征；
  2. Do：建议的解题步骤；
  3. Avoid：从失败轨迹中提取的误区；
  4. Check：边界条件和中间检查；
  5. Risk：可能的失效方式。

实验结果

  • 数学推理（DEEPMATH-103K，93K 建库 / 10K 测试，BM25 \(k=1\)）：
    • Doubao-Seed-1.8 Pro：准确率 \(95.1\% \to 94.9\%\)，Token 消耗降低 59.1%（\(3,453 \to 1,411\)），成本降低 53.8%；
    • Gemini-3-Flash：准确率 \(94.8\% \to 95.5\%\)，Token 消耗降低 18.5%，成本降低 17.5%；
    • GPT-OSS-120B：准确率维持 \(93.7\%\)，Token 消耗减少 22.4%；
    • GPT-4o-mini：准确率 \(59.6\% \to 61.4\%\)，成本降低 6.9%。
  • 编程竞赛（NEMOTRON-COMPETITIVE-PROGRAMMING-V1，26.6K 建库 / 1K 测试，混合检索 \(k=5\)）：
    • Gemini-3-Flash：pass@1 为 \(72.0\% \to 71.7\%\)，Token 消耗降低 15.5%；
    • GPT-OSS-120B：pass@1 为 \(54.2\% \to 58.3\%\)。

这些结果更准确的说法是：TRS 在部分模型上以很小的准确率变化换取较多 Token，另一些模型则同时提高了准确率。不能把它概括成对所有模型都有效。

5.2 TRS 的边界：卡片也可能干扰强模型

Scaffolding, Not Stronger Reasoning: Diagnosing Skill-Card Retrieval for Mathematical Problem Solving（ICML 2026 AI for Math Workshop / OpenReview）

这篇工作提醒：技能卡片更像外部脚手架，并不等于模型的推理能力本身得到提升。对已经能独立解决问题的模型，不适用的卡片反而可能造成干扰。

主要结论

  1. 相关性不等于适用性：文本相似只能说明主题接近，数学和代码问题还要求条件、符号和目标严格对应。
  2. 强模型也会受干扰：Top-1 卡片只要在细节上有偏差，就可能把模型从原本正确的路径带走。
  3. 干扰方式不同：
    • Top-1 卡片的主要问题是“过度谨慎的限定”（11 个案例中有 8 个），即引入题目并未要求的额外条件；
    • 较低排名卡片更容易产生符号或数值漂移，使推导变长且不稳定。
  4. BM25 分数无法直接识别风险：有害案例和正确案例的 BM25 分数差异没有统计显著性，中位数分别为 9.83 和 10.71。

六、Skill 自生成与测试时适应

静态技能库无法覆盖所有任务，因此也有工作让 Agent 从历史轨迹中生成、修改或筛选技能。不过，自生成并不天然可靠，关键仍是验证和更新条件。

6.1 SoK：技能生命周期与自生成问题

SoK: Agentic Skills — Beyond Tool Use in LLM Agents（arXiv: 2602.20867）

技能生命周期

\[ \text{发现（Discovery）}\longrightarrow\text{实践（Practice）}\longrightarrow\text{蒸馏（Distill）}\longrightarrow\text{存储（Store）}\longrightarrow\text{检索与组合（Retrieve）}\longrightarrow\text{执行（Execute）}\longrightarrow\text{评估与更新（Update）} \]

自生成技能的退化

综述引用的基准结果显示：

  • 人工整理的技能平均带来 16.2 个百分点的提升；
  • 自生成技能平均比无技能基线低 1.3 个百分点。

原因之一是模型可能把错误或过于局部的启发式写进技能。这里的结论不是“自生成一定无效”，而是生成后仍需要可执行验证、适用范围检查和版本管理。

6.2 Skills on the Fly（SkillTTA）：测试时合成临时技能

Skills on the Fly: Test-Time Adaptive Skill Synthesis for LLM Agents（arXiv: 2605.16986） 开源仓库：Hydr0pon1c/Skills-on-the-fly

现有方法的问题

  • 直接注入原始轨迹：会带入工具输出、偶发变量和无关步骤；
  • 使用静态离线技能：生成时还没看到具体测试任务，可能遗漏局部 API 或评测约束；
  • 在线强化学习：需要更新权重或显式状态，成本较高，也不适合所有闭源模型。

运行时合成

SkillTTA 在看到目标任务后，检索同类历史轨迹，再结合当前可见的任务和环境约束，生成一份临时 SKILL.md。求解模型保持固定参数。进一步的元提示优化（MPO）不直接改最终技能，而是按基准更新“怎样写临时技能”的策略，并把修改限制在可审计的槽位中。

6.3 Skill Self-Play：让技能库和训练任务共同更新

Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills（arXiv: 2607.22529）

Skill Self-Play 由出题器、求解器和技能控制器组成，目的是在任务多样性和可验证性之间取得平衡。

  1. 双流生成（Dual-Stream Generation）：
    • 技能流根据已有技能出题，保持任务结构和可验证性；
    • 开放探索流不依赖已有技能，用来发现新任务；
    • 两路数据按 \(1:1\) 混合，避免只围绕已有技能训练。
  2. 门控课程奖励（Gated Curriculum Reward）：
    • 优先选择接近当前求解器能力边界的任务；
    • 先检查任务契约是否有效，避免把不可解或格式错误的任务当成高难度样本。
  3. 技能库更新（Refine, Prune, Induce）：
    • Refine：根据失败案例修改已有技能；
    • Prune：移除已经饱和或价值较低的技能；
    • Induce：从开放探索产生的新任务中归纳技能。

6.4 SkillMOO：多目标优化技能组合

SkillMOO: Multi-Objective Optimization of Agent Skills for Software Engineering（arXiv: 2604.09297）

SkillMOO 同时考虑任务通过率、Token 成本和运行时间。求解 Agent 负责评测技能组合，优化 Agent 根据失败分析提出修改，再通过 NSGA-II 保留不同取舍下的帕累托候选。

对 38 次有效修改的统计：

  • 移除技能（16 次）：最常见的有效操作，说明删掉歧义或偏题内容可能同时改善效果和成本；
  • 替换技能（7 次）：用更具体的指令替换宽泛指令；
  • 新增技能（9 次）：这 9 次都没有提高通过率。这个结果来自论文的特定任务和搜索过程，不能直接推广为“新增技能总是无效”。

6.5 SkillsVote：技能全生命周期治理

SkillsVote: Lifecycle Governance of Agent Skills from Collection, Recommendation to Evolution（arXiv: 2605.18401）

SkillsVote 把开放技能库的管理分为收集与画像、任务前推荐、执行后归因和证据约束的更新。它不是把成功轨迹直接写回技能库，而是先区分收益来自技能、Agent 自主探索还是环境，再只保留有验证依据的可复用发现。

深入TokenPilot: Cache-Efficient Context Management for LLM Agents

⭐TokenPilot: Cache-Efficient Context Management for LLM Agents

剪裁/压缩会导致cache不连续，产生额外的成本

一个显而易见需要平衡的地方是：一方面需要减少上下文页面的长度，另一方面又需要提高硬件缓存的效率。

TokenPilot 的重点不是把文本压到最短，而是在删内容时尽量保住 prefix cache。它分成两部分：输入内容第一次进入上下文时先做规则清洗（对应全局摄入感知压缩框架）；运行过程中再根据任务状态批量逐出已经失效的片段（对应生命周期感知逐出）。

整体流程

前缀稳定化：主要是在跨任务共享KVcache时

清洗：重复读取去重、工具结果裁剪、HTML清晰、超长输出截断。

实验设置

  • PinchBench：11 类、123 个代码和办公任务；
  • Claw-Eval General：11 类、161 个沙盒多步任务；
  • Isolated Mode：每个任务结束后重置上下文；
  • Continuous Mode：同类任务放在一个长会话中连续执行。

主 Agent 使用 GPT-5.4-mini，状态评估器是 Qwen3.5-35B-A3B。论文采用的价格是： \[p_{\text{hit}}=\$0.075/\text{M},\quad p_{\text{miss}}=\$0.75/\text{M},\quad p_{\text{out}}=\$4.50/\text{M}\]

PinchBench：MemoBrain 的成本已经比较接近 TokenPilot；TokenPilot 在连续模式下仍保持了更低的总成本。

Claw-Eval：Keep-Last-N 是成本上最接近的基线之一。

连续会话中的 Token 变化：会议分析这类任务边界比较明确，上一段任务结束后就能逐出大部分旧内容，因此上下文长度较稳定。

几个比较有用的实验结论

  1. 动态字段要稳定：时间、绝对路径等字段如果每轮都变，会让前缀从很早的位置开始失效。

  2. 原文恢复不能省：禁用外部工件恢复后，Agent 会重复读文件、重复调用工具，总成本反而上升。

  3. 不能每轮都删：实验中 \(B=3\) 的综合结果最好。\(B=1\) 会频繁改写上下文，cache miss 增加；完全不逐出又会让历史持续增长。论文使用的等效输入成本是： \[\text{Equal}_{\text{input}} = C_{\text{miss}} + \alpha \cdot C_{\text{hit}} \quad (\text{如 } \alpha=0.1)\]

  4. 任务结束不等于信息立刻没用：如果刚完成任务就删掉全部相关内容，后续任务可能重新读同一个文件。Residual Utility 的作用就是给这些内容留一个缓冲期。

  5. 局限：状态评估器可能误判；方法依赖后端支持 prefix cache；主实验把同类任务放在一起，混合任务流中的复用机会会更少。论文补充实验仍有成本优势，但比同类任务连续运行时弱。

TokenPilot 论文解读：上下文压缩与前缀缓存的取舍

本文最后更新于 2026-11-07

Agent 在长会话中不断积累指令、工具调用和执行结果，每一轮都要重新携带这些历史。压缩能减少输入长度，但修改已经缓存的前缀，也可能让后续内容重新计算。上下文更短，并不必然意味着任务总费用更低。

TokenPilot 把文本压缩和前缀缓存放在一起考虑：新内容进入上下文时先清洗，运行过程中再按任务状态批量逐出历史片段。它关注的是删什么、何时删，以及删完之后还能复用多少缓存。

论文：TokenPilot: Cache-Efficient Context Management for LLM Agents，arXiv v2 · 项目仓库 LightRSI

一、前缀缓存改变了压缩的成本账

前缀缓存允许后续请求复用之前已经计算过的相同输入前缀。如果每轮主要在历史末尾追加内容，就有机会复用大段旧前缀；如果改写了靠前的片段，后面原本相同的内容也可能失去这次复用机会。

因此，比较上下文管理方法时，需要把命中缓存和未命中缓存的输入分开计数。按论文使用的计费口径：

Token 类型 每百万 Token 的价格（美元）
输入缓存命中 0.075
输入缓存未命中 0.75
输出 4.50

这里是论文实验采用的价格。令 \(N_{\mathrm{hit}}\)、\(N_{\mathrm{miss}}\) 和 \(N_{\mathrm{out}}\) 分别表示累计命中输入、未命中输入和输出 Token 数，则主模型费用为：

\[ C_{\mathrm{main}}=\frac{0.075N_{\mathrm{hit}}+0.75N_{\mathrm{miss}}+4.50N_{\mathrm{out}}}{10^6}. \]

只比较输入侧时，可以将缓存命中 Token 按价格比折算，得到等效输入量：

\[ N_{\mathrm{equal}}=N_{\mathrm{miss}}+\alpha N_{\mathrm{hit}},\qquad \alpha=0.1. \]

这个量比单纯的上下文长度更接近输入费用。不过，完整任务还会产生输出、重试和状态估计器调用，这些开销也需要计入。

二、输入时清洗，减少后续反复携带的负担

TokenPilot 的全局摄入感知压缩（Ingestion-Aware Compaction）发生在新消息进入上下文的边界。提前处理新内容，可以让后续轮次复用处理后的稳定布局。

这一部分有三项主要操作：

  • 前缀稳定化：规范化时间、路径等易变字段，并调整工具定义的布局，减少跨轮次、跨任务的前缀变化。
  • 工具观察清洗：精简 HTML 结构、重复代码和冗长日志，截断过长的执行输出，减少每轮反复携带的噪声。
  • 保留原文恢复入口：将完整工具结果放到外部工件存储中，上下文保留较短的预览；需要细节时再读取原文。

恢复入口很关键。若压缩丢掉了执行所需的信息，Agent 可能重新调用工具、分段读取文件，追加更多历史。论文的消融实验显示，关闭恢复机制后，得分下降，费用反而上升。

三、按任务生命周期批量逐出历史

输入清洗控制新增内容，生命周期感知逐出（Lifecycle-Aware Eviction）则处理已经积累的历史。TokenPilot 为任务片段维护三个状态：

任务完成和信息失去价值之间，存在一个缓冲区。例如，前一个任务处理过的会议记录，可能仍被下一个任务用于撰写报告。若在交付后立即删除相关上下文，后续任务又要重新寻找原文。

状态估计也会产生费用和布局变化。论文采用 Qwen3.5-35B-A3B 作为估计器，按固定批次触发；综合其测试中的任务得分、输入规模和调用开销，批次间隔 \(B=3\) 的取舍最好。

频繁逐出会反复改动前缀；完全不逐出又会持续携带旧历史。批量处理的作用，就是在这两项成本之间选择提交时机。

四、论文报告的实验结果

论文使用 GPT-5.4-mini 作为主 Agent，在 PinchBench 和 Claw-Eval General 上测试。前者包含 11 类、123 个任务，后者包含 11 类、161 个任务。实验分为两种模式：

  • Isolated：每个任务结束后重置上下文。
  • Continuous：多个任务在同一会话中连续执行，主实验按同类任务组织会话。

本节图表来自论文实验。

在 PinchBench 的对比中，MemoBrain 的费用已比较接近 TokenPilot；论文报告的 TokenPilot 在连续模式下仍有更低的总费用。读这组结果时，需要同时看任务得分，以及缓存命中和未命中输入分别减少了多少。

Claw-Eval 中，Keep-Last-N 是费用最接近的基线之一。固定窗口实现简单，但历史窗口移动会影响任务信息和前缀复用，这也是它与生命周期逐出值得对照的地方。

连续任务的组织方式也影响结果。会议分析这类任务边界较明确，旧片段可以在后续不再需要时逐出，使活动上下文维持在较稳定的范围内。

局限与适用条件

  • 前缀稳定化依赖后端支持前缀缓存，收益也受实际命中价格和缓存策略影响。
  • 状态估计器可能误判；逐出间隔与信息保留门槛需要适应任务分布。
  • 同类任务连续执行提供了较多复用机会。论文 v2 的混合类别补充实验扩展了这一设置，但不能覆盖所有长期任务流。
  • 模型、运行版本和任务组织方式会影响完整执行链。论文表格中的费用和得分，需连同这些条件一起理解。

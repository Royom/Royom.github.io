Agent Token Efficiency2

一、 整体研究背景与认知框架

1.1 核心目标与权衡维度

在智能体（LLM Agent）执行复杂、长程任务时，频繁的多轮环境交互与深层推理会导致上下文与输出 Token 急剧膨胀。本研究方向聚焦于 Agent Token Efficiency，探寻如何在保障（甚至提升）任务成功率的前提下，大幅削减 Token 消耗与推理开销。

在评估具体方法时，需重点考量以下几个维度： - 模型适用性：是对开源模型做权重/梯度级修改（如 SFT、RL、Attention Mask），还是通用适配商业闭源模型（Prompt 级、外部记忆、工具化调度）。 - 成本构成：不仅要关注输出 Token 与输入总 Token，还要兼顾现代 LLM API 的 KV Cache 命中率（Cache Hit vs. Cache Miss） 与定价差异。 - 信息完整性：是有损压缩（语义摘要，易丢失瞬时关键变量）还是结构化无损/可恢复保留。

1.2 技术路线全景谱系

二、 核心方向 1：智能体多轮长上下文与轨迹管理

2.1 智能体自主感知与预算管理 (Self-Management / Proprioception)

此类方法的核心假设是：成熟大模型本身具备长程管理潜能，无需对基座进行高成本微调，只需赋予其清晰的状态感知接口与自决预算工具。

1. Codex 将压缩换成上下文切换 (Token Budget Architecture)

参考来源：Codex 记忆系统设计分析

Codex CLI 把记忆系统从传统的 compaction（有损语义压缩）改成了 Token Budget（预算感知）+ 硬上下文切换。核心思路是：让模型在请求前明确知晓还剩多少 Token 预算，在适当时机主动切换到新窗口，同时用外部工具完整保留历史以备调阅。

架构分为三层： 1. 感知层（知道还剩多少）：通过 <token_budget> 标签，模型在每次请求时都能看到当前 context window 的剩余 token 数，作为自主决策的前置输入。 2. 管理层（主动切换窗口）：提供 new_context 工具。模型主动判断当前任务阶段完成，请求切换至新上下文窗口，作为 no-summary compaction checkpoint，历史不被粗暴压缩丢失，而是整块封存。 3. 记忆层（保留与精确查询）： - History 工具：列出 windows 和 items、读取 items、全文搜索历史对话。 - Notes 工具：增删改查持久化笔记（Scratchpad 机制）。

与经典工作 MemGPT 的对比： - MemGPT (2023)：设计了类似 OS 的虚拟内存分页机制，将记忆分层次（主上下文与外存向量库）并在中断机制下换入换出。 - Codex：更侧重开发者/工程化落地，采用轻量级硬切换 + 文件级查询，规避了频繁总结造成的细粒度代码与参数遗失。

2. ⭐LLM Agents Are Latent Context Managers: Eliciting Self-Managed Context via State Proprioception

比较有意思的地方：论文认为成熟的大模型经过大规模预训练已具备上下文管理能力，只是缺乏一个在上下文层的接口去感知当前状态。因此本工作设计了一个“状态仪表盘（State Proprioception）”，无需额外训练即可激发智能体的自管理。

a) 实验设置

覆盖三类不同 Token 规模与交互压力的公开基准： 1. LOCA-Bench：百万 Token 级别，极限上下文增长压力测试，75 项长任务（主测基准）。 2. BrowseComp-Plus：100K 级别长程检索研究，设极紧窗口 \(W=12\text{K}\) 测试中间证据存留。 3. GAIA：10K 级别通用多模态/通用工具智能体评测验证集（165 题）。 4. AMA-Bench：离线长程轨迹记忆迁移基准（208 个 Episode）。 - 评测基座：Gemini-3-Flash、Claude-Sonnet-4.5、DeepSeek-V4-Pro、GLM-5。

b) 论文对标的基线全景梳理

Auto-Archive + Recover 由系统后台规则自动将数据备份至外存并在需要时恢复。 属于规则驱动而非智能体自主按需搬移，易产生存取振荡与误判。
离线长程记忆模块(长轨迹问答适配) AMA Agent 针对长程历史交互轨迹设计的结构化长程记忆智能体。 系统复杂度高，针对特定记忆任务定制，单任务运行时间长。
Mem0 / EMem / BM25 基于向量检索、图记忆结构或关键词匹配的传统记忆增强适配方案。 依赖相似度检索，难以精确应对高度依赖上下文时序状态与结构的任务。

c) Token 估计误差实验

论文做的一个关键实验：在智能体执行归档时抹去仪表盘信息，让模型自主估计当前已使用了多少 Tokens。实验结果表明，模型对当前所处状态的 Token 消耗缺乏精准估计，多数估计存在显著误差，印证了显式仪表盘机制的必要性。

2.2 外部辅助模型与经验蒸馏流派 (Auxiliary Model & Distillation)

此类方法通过引入旁路的小模型、规则蒸馏或图结构，在不增加主智能体负担的前提下维护高质量的紧凑历史。

1. ACON: Optimizing Context Compression for Long-horizon LLM Agents

ICML 2026

a) 现有工作的痛点

  1. 对话摘要与检索/抽取式压缩（如 MemGPT、LLMLingua）：面向连贯对话或静态长文档检索，无法捕捉长程智能体所特有的动态因果关系、先验条件（Preconditions）与状态演变（State tracking）。
  2. 启发式截断与规则方法（如 FIFO 滑动窗口、简单 Prompt 压缩）：规则僵化、脆弱，极易误删关键的瞬时状态（如动态变量、鉴权 Token、分页游标）导致任务级联式崩溃。
  3. 模型参数联合优化方法（如 MEM1、Context-Folding）：通过强化学习（RL）将压缩策略与智能体策略参数深度绑定。此类方法必须访问模型内部权重和梯度，完全无法应用于商业闭源 API 模型（如 GPT-4/Claude 等），且多步交互下的 RL 试机（Rollout）计算开销极其高昂。

b) 核心思想与 Pipeline

一句话核心思想：用失败反思优化压缩提示，蒸馏小模型提炼记忆。

c) 实验设置

  • 核心基准：
    1. AppWorld：平均需 42.5 步交互、覆盖 9 类应用与 457 个真实 API 的高阶编码型基准。
    2. OfficeBench：跨 Word、Excel 等应用的办公工作流多步基准。
    3. 8-objective QA：长程交互搜索、多重证据协同解答基准。
    4. WebVoyager：网页端复杂交互基准。
  • 评测指标：任务成功率（Acc / EM / F1）、交互步骤（Steps）、峰值输入 Token 数量（Peak Tokens）、长程历史依赖总量（Dependency）。

2. MemoBrain: Executive Memory as an Agentic Brain for Reasoning

ACL 2026

核心特点：将记忆组织形式定义为显式因果依赖有向图；主智能体专注执行，副驾驶 MemoBrain 异步维护依赖。需要注意的是，其压缩重构机制会改变历史文本结构，破坏前缀 KV Cache。

a) 整体架构与工作流程

主智能体正常运行，副驾驶 MemoBrain 异步监听轨迹，将每轮 Episode 抽象为一个三元组 Thought（上下文来源、执行决策、语义产出）。当主智能体上下文累积到预设上限时，执行三步压缩： 1. 查询状态依赖（粉色节点）：查询全局依赖图结构与任务推进状态； 2. 折叠已完成子任务（黄色节点）：识别针对某一特定子问题且已有明确结论的连续步骤，收缩为高层摘要； 3. 剥离无效探索（灰色节点）：针对失败、已被后续更新策略取代的无效尝试，剥离细节仅保留轻量占位符。

完成后重构出紧凑、逻辑完整的受控上下文，重新注入回主智能体。

b) 实验评测

  • GAIA (General AI Assistant)：复杂多步工具调用（评估 103 道纯文本验证集，细分为 Level 1, 2, 3）。
  • WebWalker QA：包含 680 道跨多层级网页遍历的复杂信息寻检任务（分为 Easy, Med, Hard）。
  • BrowseComp-Plus：包含 830 道深度搜索研究（Deep Research）任务，使用固定候选网页库进行密集检索评估。

3. RE-TRAC: REcursive TRAjectory Compression for Deep Search Agents

方法：多轮深度搜索场景下，智能体极易在不同分支反复试错。RE-TRAC 在每轮对话完成后执行递归蒸馏总结，剔除冗余路径以避免重复探索。

实验表现与评估

  • 数据集：侧重多步深度探索基准，涵盖五个复杂搜索数据集：BrowseComp, BrowseComp-ZH, GAIA, XBench, HLE。
  • 对比基线：单次运行（Pass@1）、多数投票、加权投票和 Best-of-N。

2.3 缓存感知与系统底层优化 (Cache-Aware & System Level)

此流派不仅关注 Token 的数量，更关注 Token 的物理存放形态（KV Cache）。因为很多重写式压缩虽然削减了 Token，却打碎了前缀连续性，导致真实的 API 延迟和总账单反而上升。

d) 实验中的关键经验与技巧 (Tricks & Lessons)

  1. 静态占位符替换：必须将当前时间、动态绝对路径等频繁变动字段替换为静态占位符，防止首部前缀缓存大面积失效。

  2. 状态恢复（Recovery）机制不可或缺：若禁用外部工件恢复工具，性能将大幅下降、总成本反而上升。原因在于：缺乏完全访问权限时，智能体会产生代偿性的重复试错。

  3. Batch 大小选择：实验验证周期批次 \(B=3\) 时综合收益最佳。等效真实输入成本为： \[\text{Equal}_{\text{input}} = C_{\text{miss}} + \alpha \cdot C_{\text{hit}} \quad (\text{如 } \alpha=0.1)\]

  4. 残余效用缓冲区（Residual Utility Buffer）的重要性：如果本地任务一结束就立刻驱逐所有信息，后续任务遇到相同文档结构时就会被迫重新探索。残余缓冲区维持了任务间的上下文连贯性。

  5. 论文自述局限性：

    • 依赖轻量模型做状态分类，在模糊或稀疏交互下可能出现误判；
    • 依赖后端服务的前缀缓存支持；
    • 连续模式测试目前偏向同类任务流水线，若遇到工具调用模式剧烈跳变的极度混合任务流，前缀复用率会显著降低。

2. Leyline: KV Cache Directives for Agentic Inference

核心思路：针对中间历史 Token 变动带来的缓存失效问题，从推理引擎底层切入，采用 RoPE 旋转位置编码原地校正裁剪后的 KV 缓存。

  • 机制说明：当智能体推进到第 5 轮，决定驱逐第 2 轮的冗余信息时：
    1. 驱逐冗余 Token，插入极短的 Stub 占位符；
    2. 前缀保持不动，Stub 占位符直接插入；
    3. 后续内容的 Key/Value 向量内容不变，仅通过 RoPE 旋转操作对位置向量执行前移校正，无需重新 Prefill。

评价：属于纯推理后端与系统层工作，算法很巧，但依赖能接触到底层 KV Cache 显存与计算图的开源自建环境，商业闭源 API 无法直接应用。

2.4 启发式轨迹消解与折叠流派 (Heuristics & Folding)

  1. AgentDiet: Reducing Cost of LLM Agents with Trajectory Reduction
    • 提出一套“轨迹垃圾分类机制”：将多轮历史划分为无用（Useless）、冗余（Redundant）、过期（Expired）三类，并制定相应的规则进行精简替换。
  2. AgentFold: Long-Horizon Web Agents with Proactive Context Management
    • 专门针对网页操作智能体（Web Agents），提出一套系统性的轨迹折叠框架，将长程网页探索中的无用 DOM 交互和中间滚动状态分层折叠收缩。
  3. 共性问题：早期工作多采用硬规则删除或文本改写，较少顾及 KV Cache 破坏带来的重复 Prefill 成本。

三、 核心方向 2：单步推理链剪枝与自适应思考

除了多轮历史堆积外，另一个严重的 Token 浪费源于智能体内部的思维链（Chain-of-Thought）过度思考与冗长表述。

3.1 步骤级早停与跳过

  • Making Slow Thinking Faster
    • 核心痛点：长思考模型在输出推理链时存在大量的过度思考（Over-thinking）与无意义的反复核验。
    • 解决方案：提出“步骤熵（Step Entropy）”指标，量化评估当前推导步骤是否产生了新的信息增量。通过后训练（Post-training），引导模型在低熵推导时直接输出 [SKIP] 标记跳过无用验证，显著压缩输出 Token。

3.2 Token / 注意力级剪枝与自适应思考

  • TokenSkip: Controllable Chain-of-Thought Compression in LLMs
    • 使用小模型对原始思维链中的 Token 逐一打分，依据超参数仅保留高显著性 Token 构成紧凑推理链，以此训练大模型生成更短的思维过程。
  • CRISP: Compressing Redundancy in Chain-of-Thought via Intrinsic Saliency Pruning
    • 基于模型内部的注意力分数（Attention Saliency），在推理中动态剔除、融合或重写非关键 Token。
  • SlimSearcher: Training Efficiency-Aware Web Agents via Adaptive Reward Gating
    • 在网页搜索 Agent 中引入自适应奖励门控（Adaptive Reward Gating），通过 SFT + RL 联合训练，惩罚在简单事实问题上的过度推理。

3.3 隐式紧凑思考表示 (Gist / Cache Tokens)

LightThinker: Thinking Step-by-Step Compression

EMNLP 2025

核心思想：训练 LLM 在推理过程中动态地将冗长思考步骤压缩成紧凑的隐式表示（Gist tokens / Cache tokens），随后彻底丢弃原始推理文本，仅保留核心摘要以指导后续推导。

a) 两个核心问题：何时压缩？如何压缩？

  1. 何时压缩：通过划分思维步骤，插入特殊的控制指令 Token（如 Cache Token 和 Output Token）来引导模型自适应触发压缩。
  2. 注意力掩码控制：
    • 压缩阶段（生成思维摘要）：当需要将思维步骤 \(S_i\) 压缩入 Cache Token \(C\) 时，强制注意力掩码只能关注三项内容：① 最初的问题 \(X\)；② 历史压缩摘要；③ 当前正在处理的思考步骤 \(S_i\)。
    • 生成阶段（基于摘要生成后续思考）：当 \(S_i\) 成功压缩进 \(C\) 后，在生成后续思绪 \(S_{i+1}\) 时，掩码彻底遮蔽原始思维步骤 \(S_i\)，模型仅能依据问题 \(X\) 和所有历史摘要继续推理。

b) 闭环流程

  1. 接收问题，生成思考步骤 Thought 1；
  2. 触发压缩，将 Thought 1 压缩为紧凑摘要 CT1；
  3. 抛弃原文，从上下文中物理剔除冗长的 Thought 1；
  4. 基于初始问题与 CT1，生成 Thought 2 并循环往复。

四、 归档方向：Skill 优化与长期管理 (Archived)

暂存结论：优先以整体 Agent Token Efficiency 为核心目标，Skill 模块暂时归档，记录前期思考如下：

  1. Skill 文本自身的压缩优化：如 SkillReducer \(\to\) SkillZip，对技能说明文档和提示词进行文本级精简。
  2. 长期管理与进化机制：
    • 随任务积累，单个 Skill 长度以及 Skill 库庞大引发检索与选择成本膨胀。
    • 曾考虑采取信用分机制：调用该 Skill 通过任务则加分，失败则扣分；但难点在于需借助独立的小模型归因判断失败是否确由该 Skill 引起。
    • SkillClaw 采用了异步管理系统，将技能维护解耦给独立 LLM 优化。
  3. 关于 Skill 的过拟合与形式探讨：
    • 过拟合问题：曾见过临时合成 Skill（Skill-on-the-fly，偏离自进化本质）与开辟离线测试集校验（在线阶段开销过大）。
    • 表达形式过渡：从纯文本到代码再到参数型？文本具备高可解释性，代码适应性有限，参数型黑盒化且不易维护，因此现阶段性价比不高。

五、 个人科研思考与潜在创新点 (Research Opportunities)

结合对上述文献的梳理，当前 Agent Token 压缩领域仍存在以下明显的局限与突破切入点：

1. 从“静态规则启发”迈向“动态自适应压缩决策”

  • 现状痛点：当前代表性工作（如 TokenPilot）大多采用静态硬规则（例如固定每 3 轮批次压缩一次，观察清洗采用固定字符数截断）。这种做法容易在复杂长步骤任务中压缩过早，或在简单任务中延迟压缩。
  • 潜在路线：
    • 是否可以训练/微调一个极轻量的小策略（或利用基座内部的不确定性/注意力熵），让智能体动态决定最佳压缩时机与压缩深度？
    • 能否借鉴 State Proprioception 的仪表盘概念，让模型基于当前任务目标自主发起压缩请求？

2. 闭源商业 API 限制下的“高 Cache 命中率 + 状态低成本恢复”

  • 现状痛点：Leyline 等底层工作虽然能优雅校正 KV Cache，但闭源商业模型完全无法使用。而 ACON、MemoBrain 等重写式压缩又会彻底破坏前缀缓存，造成计费成本与延迟反弹。
  • 潜在路线：
    • 探索前缀严格保全型（Prefix-Preserving）的非破坏式压缩：只对后缀历史执行局部虚拟占位，并将中间关键工件持久化到轻量向量/键值外存中；
    • 结合 Codex 的 Token 预算感知，让智能体在 Cache 边界主动规划任务，减少跨步重复 Prefill。

3. 多模态长交互智能体（Multimodal Agent）的上下文压缩蓝海

  • 现状机遇：目前的大多数压缩工作（TokenPilot, ACON, RE-TRAC）均集中在纯文本代码、终端或文本搜索场景。
  • 创新空间：在多模态（GUI Agent、移动端自动化、网页视觉交互）中，每张截屏高保真输入动辄消耗数千 Tokens，多轮堆叠下上下文消耗呈指数级爆发。
    • 能否通过关键动作帧提取 + 视觉 Token 显著性剪枝 + 动态折叠历史截屏，构建一个兼顾视觉感知与 Token Efficiency 的多模态长程 Agent 框架？

4. 失败反思准则（ACON）与状态本体感知（Proprioception）的融合

  • 潜在路线：State Proprioception 提供了“自我感知仪表盘”，ACON 提供了“对比找差与失败自校准”。
  • 能否设计一个具有自我反思能力的闭环记忆管理系统：当智能体因遗漏信息在长程任务中遇到错误时，能够像 ACON 一样自主沉淀出对哪些上下文变量敏感，动态调整下一次由仪表盘触发的剪裁规则？

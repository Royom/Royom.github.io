ACON: Optimizing Context Compression for Long-horizon LLM Agents

ICML 2026

痛点：

  1. 对话摘要与检索/抽取式压缩（如 MemGPT、LLMLingua）：面向连贯对话或静态长文档检索，无法捕捉长程智能体所特有的动态因果关系、先验条件（Preconditions）与状态演变（State tracking）。
  2. 启发式截断与规则方法（如 FIFO 滑动窗口、简单 Prompt 压缩）：规则僵化、脆弱，极易误删关键的瞬时状态（如动态变量、鉴权 Token、分页游标）导致任务级联式崩溃。
  3. 模型参数联合优化方法（如 MEM1、Context-Folding）：通过强化学习（RL）将压缩策略与智能体策略参数深度绑定。此类方法必须访问模型内部权重和梯度，完全无法应用于商业闭源 API 模型（如 GPT-4 等），且多步交互下的 RL 试机（Rollout）计算开销极其高昂。

方法：

a) 一句话核心思想

用失败反思优化压缩提示，蒸馏小模型提炼记忆。

b) 速记版 Pipeline

  1. 对比找差：先让模型在不压缩的情况下完成任务，再在压缩记忆的情况下完成任务，找出那些“不压缩能做对、一压缩就出错”的失败过程。
  2. 诊断遗漏：让一个擅长分析的模型去对比这两份过程，明确指明是删掉了哪个具体数据（如密码、编号、执行结果）才导致了失败。
  3. 改写规则：根据诊断出的遗漏，自动修改写给记忆压缩器的“总结备忘规则”，强制它以后必须保留这类关键数据。
  4. 教出小助手：用优化好的规则生成大量优秀总结范例，直接训练一个轻量化的小模型，专门负责在后续工作中替大模型打理记忆。

c)详情

ACON 包含两大运行阶段：

阶段一：基于失败驱动的双阶段准则优化（Guideline Optimization）；

阶段二：小模型压缩器蒸馏（Compressor Distillation）。

LightThinker: Thinking Step-by-Step Compression

EMNLP 2025

训练 LLM 在推理过程中动态地将冗长的中间思考步骤压缩成紧凑的表示（gist tokens /cache tokens），然后「扔掉」原始的、繁琐的推理链，仅保留核心摘要以继续下一步的思考。 这样一来，存放在上下文窗口中的 tokens 数量被大幅削减，从而显著降低了内存占用和计算成本。

两个关键问题：「何时压缩？」和「如何压缩？」

  • 通过划分思维步骤，插入特殊的指令token，包含缓存令牌Cache Token和Output Token来告诉模型什么时候要压缩

  • 通过控制掩码限制模型能看到的内容来指导模型压缩，具体如下：

    • 压缩阶段（生成思维摘要）：当模型需要将思维步骤 Si 压缩进缓存令牌 C 时，注意力掩码会强制这些 C 令牌只能「看到」三个东西：

      • 最初的问题 X；

      • 先前已经压缩好的历史摘要；

      • 当前正在处理的思维步骤 Si。

    • 生成阶段（基于摘要生成思维）：当思维步骤 Si 被成功压缩进 C 之后，更关键的一步来了。在生成下一个思绪片段 S (i+1) 时，注意力掩码会彻底「遮蔽」掉原始的思维步骤 Si。此时，模型只能「看到」最初的问题 X 和包括刚刚生成的摘要在内的所有历史摘要 。

    通过这种方式，模型被迫学会仅依赖紧凑的「思想摘要」来进行连贯的、层层递进的推理，而不是依赖越来越长的原始思考全文。

    经过上述的训练，之后模型推导就会如下：

  1. 模型接收问题，生成第一段思考（Thought 1）。
  2. 触发压缩，将 Thought 1 中的核心信息压缩成紧凑的摘要（CT1）。
  3. 抛弃原文，将冗长的 Thought 1 从上下文中丢弃。
  4. 模型基于问题和摘要（CT1），生成第二段思考（Thought 2）。
  5. 再次压缩，将 Thought 2 压缩为摘要（CT2），并丢弃 Thought 2 原文。
  6. 如此循环，直到问题解决

Codex将压缩换成上下文切换

Codex CLI 把记忆系统从 compaction（压缩）改成了 token budget（预算）+ 硬上下文切换。核心思路是：让模型主动知道还剩多少 token，在合适时机切换到新窗口，同时用 history 和 notes 把历史完整保留下来随时查。

Token Budget 的架构可以分成三层，每层解决一个问题。

感知层：知道还剩多少。**通过 标签，模型在每次请求时都能看到当前 context window 的剩余 token 数。这是主动管理的前提。

管理层：主动切换窗口。**模型可以通过 new_context 工具主动请求切换到新的 context window。新窗口作为 no-summary compaction checkpoint，不压缩历史，直接开新窗口。

记忆层：保留和查询历史。History 工具可以列出 windows 和 items、读取 items、搜索对话内容。Notes 工具可以列出、读取、搜索、追加、写入持久笔记。

看到有人提到一篇2023年的工作 MemGPT，有一点相似之处

  1. 虚拟上下文管理：MemGPT通过智能地管理不同的memory层次，克服了LLMs的有限上下文窗口限制。通过在快速和慢速memory之间移动数据，它可以在LLM的有限上下文窗口内有效地提供扩展上下文。
  2. 中断机制：MemGPT引入了中断机制，允许用户与LLM之间的交互更为灵活。这意味着用户可以在不中断会话的情况下发送新的指令或查询。

论文对准的基线：

类别 对标基线方法 核心运作机制 主要局限性
外部规则流派 (系统底层硬处理) ReAct 纯追加历史，超出上下文窗口限制后直接强行截断旧内容。 早期关键证据被直接丢弃，长程任务中后期容易失盲。
Tool-result Clearing 当总长度超过设定的硬阈值时，自动清除旧的“工具调用-返回结果”对。 粗暴删除工具结果，后续若需用到之前的输出数据无法找回。
Fixed Stale Masking 依据静态规则屏蔽过往工具的中间输出，仅保留推理过程和调用骨架。 无法预判哪些具体输出后续仍需使用，容易误删关键信息。
智能体自压缩流派 (模型自主有损概括) SLIM 当上下文超出预算时，由模型定期对较早的历史信息进行摘要总结。 属于有损压缩，URL、ID、数据表行等高精度细节在摘要中永久丢失。
Active Context Comp. 智能体在探索过程中自主提炼知识块，随后主动修剪裁撤原始交互历史。 同样面临有损丢失细节的问题，且模型缺乏全局 Token 消耗感知。
Skeleton Compression 借鉴 Context-as-a-Tool (CAT) 设计，将过往交互压缩为紧凑的任务骨架。 压缩粒度较粗，难以保留精确的单点长尾数据。
Context-Folding 提供分支折叠与回退动作，通过策略控制工作上下文的分支状态。 依赖策略模型控制，缺乏块级的精确 Token 大小与预算感知。
工业级系统与外存 (包含外部存储机制) Claude Code (CLI) 工业级终端智能体，拥有成熟的工具链和基于本地磁盘的文件读写策略。 缺乏显式的状态仪表盘，导致盲目尝试，任务步数和 Token 消耗极高。
Auto-Archive + Recover 由系统后台规则自动将数据备份至外存并在需要时恢复。 属于规则驱动而非智能体自主按需搬移，易产生存取振荡与误判。
离线长程记忆模块 (长轨迹问答适配) AMA Agent 针对长程历史交互轨迹设计的结构化长程记忆智能体。 系统复杂度高，针对特定记忆任务定制，单任务运行时间长。
Mem0 / EMem / BM25 基于向量检索、图记忆结构或关键词匹配的传统记忆增强适配方案。 依赖相似度检索，难以精确应对高度依赖上下文时序状态与结构的任务。
